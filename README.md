# 42 Pac-Man - Ghosts! More ghosts!

A complete, playable Pac-Man in Python: four ghosts with distinct arcade
personalities, mazes generated by an externally-assigned "A-Maze-ing"
package, classical pathfinding (BFS / DFS / A\*), a persistent top-10
highscore table, a full menu-driven UI, and a cheat mode for reviewers.
The simulation is headless and deterministic; the 42 MiniLibX (MLX) is
only the window on top of it.

## Description

You are the yellow disc. Eat every pac-gum in a maze to clear the level;
clear all levels to win the game. Super pac-gums (the four corners) turn
the ghosts blue and edible for a short time. A ghost's touch costs a
life — the classic loop of *Main Menu → play → win or lose → enter your
name for the highscore → back to the menu*.

The four ghosts run one shared movement algorithm with four different
target-tile formulas: **Blinky** chases your tile, **Pinky** aims four
tiles ahead of you, **Inky** flanks using Blinky's position, and
**Clyde** pursues from afar but flees when he gets within eight tiles.
A global Scatter/Chase wave clock and a super-pacgum Frightened overlay
sit on top.

## Instructions

Requirements: **Python 3.10+**. Both native dependencies — the maze
generator and the MiniLibX graphics library — are bundled as local
wheels, so `make install` needs no network.

```bash
make install                 # create .venv, install the bundled wheels
make run                     # launch with config.json
make run CONFIG=my.json      # launch with a custom config
```

**Graphics (MiniLibX).** The game renders with the 42 MiniLibX
(`mlx_CLXV`, the official Python-wrapped MLX). A prebuilt wheel for
Linux x86_64 is vendored (it bundles a compiled `libmlx.so`). On a
different architecture/OS, rebuild it first — `make mlx` (or
`scripts/build_mlx.sh`), which needs the MLX build deps: `clang`,
`libvulkan-dev`, `zlib1g-dev`, `libxcb1-dev`, `libxcb-keysyms1-dev`,
`libbsd-dev`.

If no display is available (headless server/CI), `make run` degrades
gracefully to a textual maze preview instead of crashing.

Controls:

| Context | Keys |
|---|---|
| Move | Arrow keys or `W` `A` `S` `D` (buffered — press early into a turn) |
| Pause menu | `P` or `Esc` |
| Menus | `Up`/`Down` to move, `Enter` to select, `Esc` to back out / quit |
| Name entry | type (letters/digits/spaces, max 10), `Backspace`, `Enter` |

Cheat mode (subject VI.5, for peer review):

| Key | Effect |
|---|---|
| `F1` | Invincibility (ghosts can't take a life; still edible when frightened) |
| `F2` | Freeze ghosts |
| `F3` | Add an extra life |
| `F4` | Speed boost (hostile ghosts move at half speed) |
| `F5` | Skip the current level |

Other useful targets: `make lint`, `make lint-strict`, `make test`,
`make package`, `make debug` (runs under `pdb`), `make clean`.

  model, coordinate/bitmask conventions, ghost-AI math, pathfinding

## Configuration

The config is a JSON file (the one required CLI argument) that also
accepts `#` line comments. Every key is optional and has a safe default;
missing or invalid values are clamped and logged, unknown keys are
ignored, and the game **always** boots — the config is treated as
adversarial input because it is swapped during the defense (subject
V.3).

| Key | Default | Meaning |
|---|---|---|
| `highscore_filename` | `highscores.json` | where the top-10 table is stored |
| `level` | `[{15,15}]` | array of `{width, height}` per level |
| `lives` | `3` | starting lives |
| `pacgum` | `42` | pac-gum count target |
| `points_per_pacgum` | `10` | score for a pac-gum (X) |
| `points_per_super_pacgum` | `50` | score for a super pac-gum (Y) |
| `points_per_ghost` | `200` | score for an edible ghost (Z) |
| `seed` | `42` | level-1 maze seed (reproducible) |
| `level_max_time` | `90` | per-level time limit, seconds |

Each level's width/height is clamped to the wheel's playable minimum
(width ≥ 14 **and** height ≥ 10 — the asymmetric threshold for the "42"
logo insert) before generation.

## Highscore

A persistent JSON table of the top 10 `(name, score)` pairs, loaded at
startup and saved whenever a finished game's name is entered (subject
V.5). Names are sanitized to ≤ 10 alphanumeric-and-space characters;
scores must be non-negative integers. Loading **never raises**: a
missing, unreadable, malformed, or partially-corrupt file degrades to
"whatever valid rows could be salvaged" (empty in the worst case). The
main menu shows the top 5; a dedicated Highscores screen shows all 10.

## Maze Generation

Mazes come exclusively from the assigned wheel, always called with
`perfect=False` so its braiding pass removes dead ends and yields
Pac-Man-playable corridors (`REFERENCE.md` §1.6). Level 1 uses the
configured `seed` (reproducible); later levels draw seeds from one
session RNG seeded by that same seed, so levels differ yet the whole
game replays identically for a given config.

The wheel is quarantined behind **one file**, `pacman/maze/adapter.py`
— the only module allowed to `import mazegenerator`. It normalizes the
wheel's quirks (documented tuple-order and default-size traps, warnings
on tiny mazes, `shortest_path` returning `False`) into a single
`MazeAdapterError`, and exposes the rest of the game a clean vocabulary:
`is_walkable`, `get_valid_moves`, `neighbors`, `corners`, `center`,
`reference_path_length`, plus an ASCII renderer. If the wheel is swapped
for another group's package, only this file changes.

Walls are 4-bit masks per cell (N=1, E=2, S=4, W=8); value 15 marks the
sealed "42"-logo blocks. Positions are `(x, y)` with `y` growing
**downward**, indexed `grid[y][x]` — tested against non-square mazes so
the classic axis-swap bug can't hide.

## Implementation

- **Language / tooling:** Python 3.10+, `flake8` + `mypy` (mandatory
  flags **and** `--strict`) clean, `pytest` suite of 216 tests.
- **Entry point:** `pac-man.py <config.json>` — exactly one argument;
  wrong arg count or any maze/display failure prints a clean message,
  never a traceback.
- **Engine (`pacman/game/`):** `GameState` + `update_game_state` own all
  mutable world state and advance it in fixed *ticks* (10/second), never
  wall-clock time — so pause is trivial and the whole game is unit-
  testable headless. The canonical per-tick order (snapshot → timers →
  player → ghosts → collisions → pellets) is load-bearing: collision
  resolution is a single post-movement pass covering **both**
  co-location and the tile-swap (pass-through) case. `GameSession`
  handles ≥ 10 levels, seeding, and carrying score/lives across levels.
- **Ghost AI (`pacman/ai/`):** three decoupled layers — *when* (a
  Scatter/Chase wave clock + Frightened overlay), *what* (the four
  per-ghost target formulas), and *how* (path-based navigation toward
  the target). Frightened flight stays a seeded random walk.
- **Pathfinding (`pacman/pathfinding/`):** standalone BFS / DFS / A\*
  (Manhattan heuristic) validated against the wheel's own solver as an
  oracle across ~150 seeds; A\* provably never expands more nodes than
  BFS. Wired into gameplay: ghosts navigate (and eaten "eyes" return
  home) by the A\* next hop, so they hunt instead of orbiting walls.
- **UI (`pacman/ui/`):** split into `shell.py` — a platform-neutral
  screen FSM (`MAIN_MENU`, `INSTRUCTIONS`, `HIGHSCORES`, `PLAYING`,
  `PAUSED`, `NAME_ENTRY`) driven by abstract `Action` inputs, with the
  fixed-timestep clock (sim at 10 Hz via a time accumulator, so speed is
  frame-rate independent) — and `app.py`, the MLX driver that renders
  the shell's state and translates MLX keys into `Action`s. Only
  `app.py` imports MLX, so the whole UI is unit-tested without a window.
- **Highscore (`pacman/highscore/store.py`)** and **config
  (`pacman/config/loader.py`)**: both self-contained and hardened
  against bad files.

## General Software Architecture

The codebase is layered so each layer depends only on the ones below it,
and each is testable in isolation:

```
        pac-man.py (CLI)              packaging/make_package.py
              |
        ui/app.py  (MLX driver — the ONLY importer of mlx)
              |
        ui/shell.py  (screen FSM + input, no graphics lib)
              |
   game/session.py  ->  game/engine.py  (headless, tick-based, OOP)
        |          \          |        \
   ai/* (ghosts,    highscore/store   pathfinding/*  (standalone)
    wave, targeting,        |               |
    intersection)          (files)   graph.py Protocol
              \                            /
               maze/adapter.py  (the ONLY importer of the wheel)
                        |
              mazegenerator wheel (third-party, as-is)
```

Two boundaries carry the design:

1. **The wheel anti-corruption layer.** All third-party quirks are
   absorbed in `maze/adapter.py`; the rest of the game speaks only the
   adapter's vocabulary. Pathfinding depends on a tiny `MazeGraph`
   *Protocol* (structural typing), so it imports nothing from the maze,
   game, or UI layers.
2. **Headless engine + platform-neutral shell / thin MLX view.** The
   engine and the UI shell know nothing about MLX; only `ui/app.py` does.
   This is what lets 216 tests drive the entire game — engine *and* the
   full screen FSM — tick-by-tick without ever opening a window (MLX's C
   loop cannot run headless).

**A noted design choice:** player state (tile, facing, buffered input,
lives) lives as cohesive fields on `GameState` rather than in a separate
`Player` class. `GameState` is the encapsulated owner of all world
state, which keeps the load-bearing per-tick ordering and the tile-swap
snapshot logic in one auditable place; ghosts, by contrast, *are* a
dedicated `Ghost` class because there are four independent instances
with their own AI state.
